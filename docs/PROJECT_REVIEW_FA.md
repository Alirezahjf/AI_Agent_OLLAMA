> تاریخ مرور: ۲۰۲۶-۰۸-۱۱

## ۱) این پروژه چیست؟

یک **عامل هوشمند فارسی‌زبان** با دو بستهٔ مستقل که هیچ کدی با هم به اشتراک نمی‌گذارند:

| بسته | خط کد | نقش | وضعیت |
|---|---|---|---|
| `agent/` | ~۲۹۰۵ | ربات تلگرام/بله روی سرور: فایل، کد، command، وب‌اسکرین‌شات | ✅ بالغ و پایدار |
| `local_agent/` | ~۱۹۸۶۷ | دستیار دسکتاپ (ویندوز/لینوکس): GUI، تلگرام شخصی، Task Manager، فایل، shell | ⚠️ یک باگ بحرانی |

- **۱۲۳ فایل پایتون**، در مجموع ~۲۲٬۸۰۰ خط کد.
- **۵۷۲ تابع تست**: ۶۹ تست در `tests/` (agent) و ۵۰۳ تست در `tests_local_agent/`.
- پشتیبانی از سه ارائه‌دهندهٔ مدل: **Ollama** (محلی)، **GapGPT** و **AvalAI** (سازگار با OpenAI).
- رابط‌های متعدد در `local_agent`: اپ دسکتاپ، رابط وب FastAPI، CLI، ربات تلگرام/بله — همه روی یک Bridge مشترک.

## ۲) نقاط قوت (چشمگیر)

### امنیت و sandboxing
این پروژه با **نگرش امنیتی جدی** نوشته شده، نه صرفاً یک wrapper دور LLM:

- **محدودسازی مسیر**: همهٔ pathها با `resolve()` زیر `WORKSPACE_ROOT` کنترل می‌شوند؛ خروج از workspace ممنوع است.
- **حفاظت فایل‌های حساس**: خواندن/نوشتن `.env`، credential، کلید SSH و مسیرهای `.ssh/.aws/.gnupg` مسدود است.
- **Hard-block دستورات مخرب**: هم POSIX (`rm`, `mkfs`, `git clean`, `git reset --hard`, `curl|sh` …) و هم ویندوز (`del`, `format`, `diskpart`, `Remove-Item` …) — فقط در موقعیت executable چک می‌شوند تا `npm run format` کار کند.
- **تشخیص مسیر خارج از workspace در command**: مسیرهای مطلق به `AppData` یا پروفایل کاربر رد می‌شوند؛ URLها استثنا می‌شوند.
- **دستورهای read-only** فقط یک زیرمجموعهٔ کوچک و بدون shell-chaining هستند (`dir`, `type`, `findstr`, `ls`, `cat`, `git status` …).

### بهداشت خروجی مدل (ضد prompt injection)
- **نرمال‌سازی Markdown link**: مد زیر خط `check_[pw.py](http://pw.py)` را به `check_pw.py` تبدیل می‌کند و URL مخفی را هرگز اجرا نمی‌کند. لینک‌های ناقص به‌جای رسیدن به shell، `ToolError` می‌دهند.
- **قاب‌بندی خروجی ابزار به‌عنوان «دادهٔ غیرقابل‌اعتماد»**: نتیجهٔ فایل/وب با `[TOOL_RESULT | داده، نه دستور]` احاطه می‌شود تا تزریق دستور در نوبت بعد کم‌اولویت شود.

### معماری و کیفیت اجرا
- **حلقهٔ عامل محدود** (`MAX_AGENT_TURNS`) — از loop بی‌پایان جلوگیری می‌کند و صادقانه توقف را گزارش می‌دهد.
- **نوشتن اتمیک فایل** (tmp + replace) و `patch_file` با تطابق دقیقاً یک‌باره.
- **کلید API هرگز در SQLite ذخیره نمی‌شود** — فقط در RAM جلسه (session)؛ منبع کلید فقط «ENV/جلسه» گزارش می‌شود، نه خود کلید.
- **retry/backoff نمایی با jitter** برای خطاهای گذرا (۴۲۹/۵xx/timeout/SSL EOF) و fallback `flex → default` در AvalAI.
- **تمیز کردن base URL مچ‌شده**: `https://[api.avalai.ir](http://...)/v1` به URL درست تبدیل می‌شود.
- **degradation بدون crash**: نبود cmd.exe/bash پیام فارسی خوانا می‌دهد، نه exception.
- تست‌های `agent/` **همه سبز** (۹۱/۹۱) و کد نسبتاً تمیز.

### اسناد و تجربهٔ کاربری
- ۲۰ فایل Markdown (README، DESKTOP، WEB_UI، BRIDGE، DESIGN).
- README بسیار کامل با مثال‌های واقعی، هشدارهای امنیتی صریح، و توضیحات فارسی روان.

## ۳) 🔴 باگ بحرانی کشف‌شده (با اثر بالا)

**فایل:** `local_agent/actions/telegram_actions.py`

در حلقهٔ ثبت اکشن‌ها (خطوط ۳۰۸–۳۱۳)، **پنج تابع رفرنس داده شده‌اند اما تعریف نشده‌اند**:

```python
("telegram.get_sessions",      get_sessions,            ...)  # ❌ تعریف‌نشده
("telegram.terminate_session", terminate_session,       ...)  # ❌ تعریف‌نشده
("telegram.get_privacy",       get_privacy_settings,    ...)  # ❌ تعریف‌نشده
("telegram.export_chat",       export_chat,             ...)  # ❌ تعریف‌نشده
("telegram.bulk_send",         bulk_send,               ...)  # ❌ تعریف‌نشده
```

### اثر
این `NameError` در زمان **import** ماژول رخ می‌دهد. چون این ماژول در رجیستری مرکزی اکشن‌ها بارگذاری می‌شود، **کل سیستم اکشن `local_agent` خراب می‌شود**: رابط وب، WebSocket Bridge، CLI، اپ دسکتاپ و ربات تلگرام.

### شواهد تست
- `tests_local_agent`: **۶۹ شکست + ۸۴ خطا = ۱۵۳ تست مشکل‌دار**.
- **همهٔ ۱۵۳ مورد از همین یک `NameError` سرچشمه می‌گیرند** (۱۵۱ مورد با متن `name 'get_sessions' is not defined`).
- **صفر شکست ناشی از ماژول نصب‌نشده** — یعنی احتمالاً با تعریف این ۵ تابع، کل سوئیت `local_agent` سبز می‌شود.

### توجیه ریشه‌ای
به نظر می‌رسد در حین اضافه‌کردن «قابلیت‌های God-Mode» تلگرام، تعریف توابع فراموش شده یا در یک ادغام/ریست گم شده‌اند. (تاریخ git به یک commit فشرده است، پس ردیابی دقیق ممکن نیست.)

> **پیشنهاد:** این پنج تابع باید پیاده‌سازی شوند (یا اکشن‌های مرتبط از رجیستری حذف شوند) تا `local_agent` دوباره کار کند.

## ۵) ملاحظات معماری

1. **دو بستهٔ مستقل، کد تکراری**: هر دو `config.py`، `providers.py` و مفاهیم مشابه storage دارند. README صراحتاً می‌گوید عمدی است، اما بار نگهداشت می‌سازد. در بلندمدت یک لایهٔ مشترک `common/` می‌تواند کمک کند.
2. **نام مدل‌های ابری** (مثل `gpt-5.6-sol`، `claude-sonnet-5`، `kimi-k2.7-code`) صرفاً پیش‌فرض‌های ارائه‌دهنده‌اند و بی‌ضررند، ولی اگر کاربر انتظار مدل واقعی دارد، باید با `GET /models` صحت بگیرد.
3. **تاریخ git فشرده** (یک commit) — قابلیت ردیابی تکامل پروژه و bisect را محدود می‌کند.
4. **عملیات مخرب در `local_agent`** (kill پروسس، ارسال پیام انبوه، terminate session) قدرتمند اما خطرناک‌اند؛ لایهٔ `Risk` (SAFE/DESTRUCTIVE/SYSTEM) و تأیید هوشمند طراحی شده، که باگ بالا را مهم‌تر می‌کند چون تا زمان اصلاح، **هیچ** اکشن تلگرامی در دسترس نیست.
